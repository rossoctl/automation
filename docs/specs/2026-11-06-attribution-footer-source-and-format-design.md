# Attribution Footer: Source Repo + Format Design

**Status:** approved (design settled 2026-11-06)
**Closes:** rossoctl/automation#131
**Resolves (partially):** rossoctl/repoman#10 — its "attribution source is per skill"
bullet is superseded here by uniform `rossoctl/repoman` (see below). #10's remaining live
work (the create-only `_meta` migration of files still pinned to `agent-skills`) is NOT in
this spec. Note: #10's "wire pr-review/weekly-report into `skill_attribution`" premise is
already stale — both already call it and emit to GitHub + Slack, so this change fixes them
uniformly with no wiring needed.

## Problem

Every RepoMan program appends an attribution footer via `skill_attribution()` in
`scripts/github-api.sh`. Today it reads, e.g.:

```
Generated by RepoMan github-pr-review@235a7f7 (https://github.com/rossoctl/agent-skills/blob/235a7f7.../skills/github-pr-review/SKILL.md).
```

Three defects:

1. **Casing.** "RepoMan" should be the lowercase project/repo name `repoman`.
2. **Not a link.** The SHA and URL are plain text; they should render as a markdown
   link `[<skill>@<sha>](<url>)`.
3. **Wrong source repo (→ 404, #131).** The URL is built from a single global
   `SKILL_SOURCE_REPO` defaulting to `rossoctl/agent-skills`. Repoman-native skills do
   not live there, so their footer links 404 — and this worsens once the repoman-native
   skills are removed from agent-skills (planned). `resolve_skill_meta` already *writes*
   a per-skill `.source`, but nothing consumes it and it is only ever the one global.

## Design

### Single source of truth: `rossoctl/repoman`

At release time, **every** skill in the bundle is vendored into `rossoctl/repoman`
(including `github-pr-review`, which is vendored on each new release). So the footer's
"where this skill lives" is uniformly `rossoctl/repoman` — the repo state the release was
cut from. There is **no per-skill source map and no exception**: a skill whose pinned SHA
does not resolve in repoman is a maintainer inconsistency, not a case for the footer logic
to special-case.

Verified (2026-11-06): the commit-path lookup
`repos/rossoctl/repoman/commits?path=skills/<name>` resolves for every bundled skill,
including `github-pr-review` (sha `a0b39d3`) and `dep-bump-scanner` (`e5cf3fe`).

**Change:** flip the `SKILL_SOURCE_REPO` default from `rossoctl/agent-skills` to
`rossoctl/repoman` (`scripts/github-api.sh:204`). It stays an env-overridable default
(tests pin it). Because it now matches where skills actually live, the per-skill `.source`
that `resolve_skill_meta` writes becomes meaningful (records `rossoctl/repoman`) rather
than a dead copy of a wrong global.

### Footer wording + format

`skill_attribution()` (`scripts/github-api.sh`, the two `printf` branches) changes from:

```
Generated by RepoMan <skill>@<sha> (https://github.com/<repo>/blob/<sha>/skills/<skill>/SKILL.md).
```

to:

```
Generated by repoman [<skill>@<sha>](https://github.com/<repo>/blob/<sha>/skills/<skill>/SKILL.md).
```

- `RepoMan` → `repoman`.
- The `<skill>@<sha>` text + blob URL become a single markdown link.
- The link target is unchanged: the skill's `SKILL.md` **blob at the pinned SHA** (not a
  commit URL).
- The no-SHA fallback branch (unresolved provenance) keeps its `blob/main` form, updated
  to the same `repoman` casing + markdown-link shape.

## Out of scope

- `resolve_skill_meta`'s create-only `_meta` semantics and migration of pre-existing
  `_meta` files pinned to `agent-skills` — the `.source` mismatch handling is its own
  concern (overlaps repoman#10). This spec only changes the *default* and the *format*;
  it does not add `_meta.source`-vs-current-source reconciliation.
- Removing the repoman-native skills from agent-skills (planned separately). This design
  is already correct before and after that cleanup because nothing points at agent-skills.

## Deliverables

1. `scripts/github-api.sh`: `SKILL_SOURCE_REPO` default → `rossoctl/repoman`; both
   `skill_attribution` `printf` branches → `repoman` + markdown-link format.
2. Update the unit tests that assert the footer string — `tests/test-skill-meta.sh`,
   `tests/test-attribution-consumers.sh`, and `tests/test-weekly-report.sh` (its exact-match
   `FALLBACK`) — to the new casing/format, watching them fail first (the old strings) then pass.
3. Re-vendor into `rossoctl/repoman` (separate step/PR; `vendor-engine.sh` run + stamp).

## Acceptance criteria

- [ ] Footer reads `Generated by repoman [<skill>@<sha>](<blob-url-at-sha>).`
- [ ] The blob URL host is `rossoctl/repoman` for every bundled skill.
- [ ] `github-pr-review`'s footer resolves (no 404) against `rossoctl/repoman`.
- [ ] `SKILL_SOURCE_REPO` env override still works (tests pin it).
- [ ] Footer-asserting unit tests updated and green; shellcheck clean.
